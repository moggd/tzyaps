# Дефекти публічного demo OrangeHRM

Середовище — публічний OrangeHRM, Chrome 158.0.8127.37, macOS 27.2.1, 28.11.2026. Виконавець — Codex. Використано власні синтетичні записи бригади. Докази прогона А в [журналі](execution-log.xlsx). Попередні твердження й знімки доступні в історії Git. Ідентифікатори нових звітів локальні до реєстрації.

## BUG-002 · Admin зберігає Username із забороненими символами

**F-30, TC-006 і TC-025.** Major, P3, Open. [Наявний Issue #1](https://github.com/moggd/tzyaps/issues/1).

1. Увійти під опублікованим Admin. Створити власного працівника KpiC у PIM.
2. Відкрити Admin → User Management → Users → Add.
3. Обрати ESS, щойно створеного працівника і статус Enabled.
4. Ввести унікальне ім’я з кирилицею й підкресленням, наприклад `КпіС_0kfo`. У другій спробі використати ім’я із пробілом, наприклад `KpiC 2oo9`.
5. Заповнити Password та Confirm Password валідним тестовим паролем і натиснути Save.
6. У System Users виконати пошук за точним введеним Username.

**Очікувано.** Відхилити ім’я, що містить символи поза латинськими літерами та цифрами.
**Фактично.** В обох варіантах система створила активний ESS і повернула відповідний запис за точним іменем.
**Вплив.** Порушено правило цілісності імені. Створення та вхід загалом доступні, виправлення можна планувати без зупинки demo.
**Докази.** [TC-006](attachments/agent-run/TC-006.png), [TC-025](attachments/agent-run/TC-025.png).

## BUG-010 · Політика дозволяє створити ESS із паролем із семи символів

**GUI-50, S-10, TC-021.** Major, P2, Open.

1. Під Admin відкрити Add User. Установити ESS, власного працівника KpiC, Enabled та унікальний валідний Username.
2. У Password і Confirm Password ввести однакове синтетичне значення рівно із семи символів, серед яких є велика літера, цифра і спецсимвол.
3. Натиснути Save. У System Users виконати точний пошук за новим ім’ям.

**Очікувано.** Через довжину <8 створення відхилено.
**Фактично.** Запис збережено. Контрольний пошук повернув створеного користувача.
**Вплив.** Застосунок допускає коротший пароль за встановленим мінімумом.
**Докази.** [Форма](attachments/agent-run/TC-021-input.png), [результат пошуку](attachments/agent-run/TC-021.png).

## BUG-003 · Політика дозволяє пароль без великої латинської літери

**GUI-50, S-10, TC-022 і TC-042.** Major, P2, Open.

1. Під Admin відкрити Add User. Установити ESS, власного працівника KpiC, Enabled та унікальний валідний Username.
2. У Password і Confirm Password ввести однакове тестове значення з дев’яти символів, з малою літерою, цифрою та спецсимволом, без великої літери. TC-022 додатково перевіряє поєднання двох відсутніх класів.
3. Натиснути Save. Знайти новий запис за точним Username.

**Очікувано.** Політика складу відхиляє пароль. Довжину виконано.
**Фактично.** Запис створено та знайдено. TC-042 підтверджує прийняття за наявності спецсимволу.
**Вплив.** Під час реєстрації можна обрати пароль із меншим набором класів символів, ніж вимагає SRS.
**Докази.** [TC-042, форма](attachments/agent-run/TC-042-input.png), [TC-042, результат](attachments/agent-run/TC-042.png), [комбінований TC-022](attachments/agent-run/TC-022.png).

## BUG-001 · Перевірка чинної картки про XML

[Issue #2](https://github.com/moggd/tzyaps/issues/2) стосується F-130. У TC-018 і TC-023 після збереження активної вакансії форма містила RSS Feed URL. Перехід за адресою повернув HTTP 200, XML і назву синтетичної вакансії. Це відповідає доступності вакансії у XML за чинним формулюванням SRS 1.1. Потребу в окремому XML-файлі або кнопці SRS не встановлює. Запропоновано погодити тлумачення та закрити як Closed (not reproducible) за результатом регресії. [Форма](attachments/agent-run/TC-018-form.png).

## BUG-011 · Політика дозволяє пароль без спеціального символу

**GUI-50, S-10, TC-043.** Major, P2, Open.

1. Під Admin відкрити Add User для власної картки KpiC. Установити ESS, Enabled та унікальний валідний Username.
2. Увести в обидва поля значення з дев’яти символів, яке має великі та малі літери й цифри, без спецсимволу.
3. Натиснути Save і знайти новий запис за точним Username.

**Очікувано.** Політика відхиляє пароль через відсутність спеціального символу.
**Фактично.** У TC-043 створений користувач збережений і знайдений. Межа довжини й правило великої літери виконані.
**Вплив.** Окрема вимога до складу пароля відсутня у валідації. Виправлення зачіпає створення ESS.
**Докази.** [Введення](attachments/agent-run/TC-043-input.png), [збереження](attachments/agent-run/TC-043.png).

## BUG-013 · Підсумок годин недоступний у режимі редагування табеля

**GUI-80, TC-035.** Normal, P2, Open.

1. Увійти власним ESS. Підготувати власний поточний табель з одним рядком, валідними Project і Activity.
2. Відкрити Time → My Timesheet → Edit.
3. Ввести 07:30 для понеділка, перевести фокус.
4. Перевірити стовпець та рядок Total перед Save.

**Очікувано.** Видно обидва підсумки, вони оновлюються після редагування.
**Фактично.** Є дні від понеділка до неділі. Стовпець Total і підсумковий рядок під час редагування відсутні. Після Save підсумок доступний.
**Вплив.** Під час заповнення працівник не бачить загальні години. Перевірка можлива після збереження.
**Доказ.** [Редагування](attachments/agent-run/TC-035-edit.png).

## BUG-014 · Підтвердження успіху з’являється в лівому нижньому куті

**GUI-90 редакції 1.1, TC-036.** Trivial, P3, Open.

1. На viewport 1280×720 увійти як Admin, відкрити PIM → Add Employee.
2. Ввести власні синтетичні First Name і Last Name з префіксом KpiC.
3. Натиснути Save. Зафіксувати положення Success / Successfully Saved.

**Очікувано.** Зелена підказка у правому нижньому куті.
**Фактично.** Підказка зліва внизу. У повторі центр мав x=212 при ширині 1280 та y=662 при висоті 720.
**Вплив.** Візуальне відхилення. Створення картки та підтвердження доступні.
**Доказ.** [Сповіщення А](attachments/agent-run/TC-036-toast.png), [повтор B](../sprint5/attachments/manual/TC-036-toast.png).

## BUG-015 · Обов’язкові поля входу без зірочок

**GUI-40, U-10, TC-039.** Minor, P3, Open.

1. У новій сесії відкрити сторінку Login.
2. Оглянути підписи Username і Password до введення.
3. Натиснути Login з порожніми полями, щоб підтвердити обов’язковість.

**Очікувано.** Біля обох обов’язкових підписів є зірочки. Порожні значення викликають Required.
**Фактично.** Зірочок немає. Перевірка порожніх значень працює.
**Вплив.** Візуальна вказівка на обов’язковість з’являється лише після взаємодії з формою. Вхід доступний.
**Докази.** [Підписи Login](attachments/agent-run/TC-039.png), [Required](attachments/agent-run/TC-032.png).

## BUG-016 · ESS зберігає зміну фото власного профілю

**Вимога F-60, TC-047.** Normal, P3, Open. Прогін A та незалежний повтор B на двох синтетичних облікових записах.

**Передумова.** Власний синтетичний працівник з роллю ESS. Підготовлено PNG із геометричною фігурою.

1. Увійти під власним ESS та відкрити **My Info**.
2. Натиснути поточне фото у бічній панелі своєї картки.
3. У формі Change Photograph обрати синтетичний PNG, натиснути **Save**.
4. Перезавантажити сторінку й оглянути фото в бічній панелі.

**Очікувано.** ESS редагує тільки контактні дані за F-60. Фото не зберігається з цього облікового запису.

**Фактично.** У двох спробах показано Successfully Updated. Після перезавантаження в бічній панелі залишилося нове фото. SHA-256 зображення, яке повернув застосунок у межах власної авторизованої сесії, збігся із SHA-256 завантаженого зразка.

**Вплив.** Працівник може змінити непередбачений атрибут власної картки. Основні сценарії роботи доступні.

**Докази.** [Вхідний PNG A](attachments/agent-run/TC-047-input.png) · [фото після перезавантаження A](attachments/agent-run/TC-047.png) · [вхідний PNG B](../sprint5/attachments/manual/TC-047-input.png) · [фото після перезавантаження B](../sprint5/attachments/manual/TC-047.png).
