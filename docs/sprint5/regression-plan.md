# План регресії «Персонал+»

Зафіксовано до перевірки v2. Обсяг — усі TC спринту 3, усі методи й набори даних JUnit та всі сценарії WebDriver спринту 4, окрема повторна перевірка відкритих дефектів. Для UI обидва проходи використовують поточний публічний OrangeHRM. Версії v1/v2 належать лише Java-модулю. Дати фактичних запусків фіксуються в журналах.

| Критерій випуску | Поріг | Обґрунтування |
|---|---|---|
| К1. Відкриті Blocker або Critical | 0 | Неприпустима втрата основної функції або коректного розрахунку оплати. |
| К2. Покриття вимог тестами | High 100%, загальне ≥75% | Усі ключові кадрові операції та фінансові правила потребують контролю. Для обмежень публічного стенду потрібні пояснення. |
| К3. Успішні перевірки серед Passed + Failed | ≥90% | Щонайбільше одна з десяти виконаних перевірок може відхилятися від очікуваного. Blocked звітуються окремо. |
| К4. Відкриті регресійні дефекти | 0 | Оновлення має зберігати поведінку, яка відповідала SRS у v1. |

Усі чотири критерії обов’язкові. Пороги обрано для цього плану на основі прикладу методички С5 §§3.5, 3.8. Непідтверджений обов’язковий критерій виключає рекомендацію Go. Покриття проєктування, фактичне виконання та особистий внесок команди обліковуються окремо.

За статутом С5 Марко відповідає за критерії та рішення, Антон — за прогони, Артем — за матрицю та метрики, Роман — за рецензію. Фактичний виконавець технічної перевірки вказується окремо. Перед захистом команда перевіряє журнал, розглядає заблоковані передумови та ухвалює власне рішення.

За §3.8 кожен Blocked потребує повтору або обґрунтованого виключення. Стан залишкових блокувань наведено у журналі. Уточнення додано під час оформлення звіту. Числові пороги К1–К4 збережено.
