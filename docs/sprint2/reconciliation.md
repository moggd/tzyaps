# Застосування вимог у спринтах 3–5

У локальній редакції SRS 1.1 журнал змін є джерелом прийнятих правок до оригінальної SRS П3. Стислі абзаци після журналу не відтворюють усіх правил. Для тестів використано незмінені частини вихідних формулювань і 11 точкових правок, включно з renumber F-100 та обмеженням BL-50. Правила BL і контрольні дані наведено у [матриці С4](../coverage-matrix.md). Пріоритети простежено у [матриці С5](../sprint5/traceability-matrix.xlsx).

| Умова | Наслідок для перевірки |
|---|---|
| F-20 «Invalid credentials» і GUI-20 «Wrong username or password» | Відмову й повідомлення перевірено за F-20. Єдиний текст для GUI-20 потребує узгодження. |
| F-110 одночасно включає й виключає Pending Approval з балансу | Перевірено призначення ліміту. Формула для Pending Approval потребує узгодження. |
| F-130 вимагає XML для експорту | Для тесту перевіряється наявність конкретної активної вакансії в доступному XML. Окремий файл на кожну вакансію у правці не визначено. |
| GUI-90 та повідомлення після збереження | Редакція 1.1 прив’язує GUI-90 до сповіщення. Склад форми кандидата частково перевірено в межах F-140. |
| План С2 передбачає навантажувальні та інші стендові перевірки | Для цих робіт потрібен окремий налаштований стенд. На публічному demo виконано предметні сценарії зі штучними даними, а модуль протестовано локально. |
| BPMN і опис рецензії С1 | У моделі найму не підтверджено окрему гілку відмови кандидата. У моделі відпустки не підтверджено окремий об’єкт заявки й цикл виправлення працівником. Розбіжності зафіксовано для захисту. |
