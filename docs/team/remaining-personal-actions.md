# Особисті дії до здачі

| Хто | Дія та доказ | Час без налаштування |
|---|---|---|
| Кожен студент | Написати три власні методи, передати файл Марку, створити власний коміт у GitHub Web після дозволу на публікацію. На своєму робочому місці виконати два стартерні запуски. [Картки й шаблони](participation.md) | 10–20 хв на код, 2–5 хв на коміт, 3–5 хв на стартовий запуск |
| Кожен студент | Одним повідомленням прив’язати уже подану рецензію до класу та редакції. Уточнити розбіжності за [готовими запитами](review-confirmations.md). | 2–5 хв |
| Антон, Марко, Роман і колега для класу Марка | Антон перевіряє нові TC-047–048 і звіряє точні BUG-ID. Марко перевіряє класи колег С4, колега — клас Марка. Роман перевіряє оновлені показники та висновок С5. Передати ID, версію й висновок. | 5–10 хв кожному після отримання матеріалів |
| Усі четверо | Долучитися до фактичного ретро і захисту за ролями. Кожен окремо надсилає викладачу анонімну peer-review. Письмову заміну ретро погоджує викладач. [Ретро](retro-preparation.md) · [Захист](defense-cards.md) | 15 хв на ретро за методичкою, близько 15 хв на загальний захист |
| Один учасник, який раніше не бачив Apply Leave, і спостерігач | Виконати U-20. Передати час і статус власної заявки. [Картка](u20-observation.md) | До 3 хв на завдання, окремо перевірка фікстури |
| Марко та викладач | Отримати визначений поріг S-20 і погодити зарахування ролі ТА через додаткове завдання Антона. Антон готує погоджений аналітичний артефакт. | Одне коротке звернення, час виконання за обсягом задачі |
| Марко | Підтвердити публікацію гілки та пакета Issues. За потреби пройти штатний вхід GitHub. | 2–5 хв |

Після отримання особистих комітів технічну збірку, порівняння v1/v2 та перерахунок показників можна виконати централізовано. [Ролі](charter.md)
