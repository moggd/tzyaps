# Характеристика продукту «Персонал+»

## 1. Профіль компанії і продукту
«Персонал+» — це хмарна HRM-система для компаній на 100-1000 працівників. Головна цінність: переведення рутинних операцій на самообслуговування для зменшення навантаження на HR-відділ.

## 2. Користувачі та ролі
* **Працівник:** переглядає профіль, подає заявки на відпустку.
* **Керівник підрозділу:** погоджує заявки та табелі підлеглих.
* **HR-менеджер:** веде картки працівників, вакансії, призначає ліміти.
* **Адміністратор:** керує налаштуваннями системи, створює облікові записи.
* **Система:** автоматизований учасник, що виконує розрахунки та перевірки.

## 3. Бізнес-процеси
Згідно з легендою, ключовими процесами є: Найм працівника, Подання й погодження відпустки, Облік робочого часу (табель), Звільнення.
**Змодельовано процеси:** «Найм працівника» та «Подання й погодження відпустки».

### Таблиця елементів моделі 1: «Найм працівника»
| Пул / Доріжка | Тип елемента | Назва й опис |
|---|---|---|
| Компанія / Керівник | Початкова подія | Запит на вакансію |
| Компанія / HR | Задача | Створити вакансію |
| Кандидат | Подія-повідомлення | Подати резюме (потік повідомлення до HR) |
| Кандидат | Об'єкт даних | Резюме (асоціація до кроку подання) |
| Компанія / Керівник | Задача | Провести співбесіду |
| Компанія / Керівник | Шлюз XOR | Кандидат підходить? (Так / Ні -> Кінцева подія "Відхилено") |
| Компанія / HR | Задача | Надіслати офер |
| Кандидат | Шлюз XOR | Кандидат приймає? (Так / Ні -> Кінцева подія "Кандидат відмовився") |
| Компанія / HR | Шлюз AND | Розгалуження ТА (паралельне створення) |
| Компанія / HR | Задача | Створити картку працівника |
| Компанія / Адмін | Задача | Створити обліковий запис |
| Компанія / HR | Шлюз AND | Синхронізація гілок створення |
| Компанія / HR | Згорнутий підпроцес | Онбординг у перший день |
| Компанія / HR | Кінцева подія | Успішний найм |

### Таблиця елементів моделі 2: «Подання й погодження відпустки»
| Пул / Доріжка | Тип елемента | Назва й опис |
|---|---|---|
| Працівник | Початкова подія | Потреба у відпустці |
| Працівник | Задача | Подати заявку |
| Працівник | Об'єкт даних | Заявка на відпустку |
| Система | Задача | Розрахувати дні та перевірити баланс |
| Система | Анотація | Тривалість рахується лише в робочих днях (до розрахунку) |
| Система | Шлюз XOR | Баланс достатній? (Ні -> Кінцева подія "Відхилено системою" / Так -> до Керівника) |
| Керівник | Задача | Розглянути заявку |
| Керівник | Межова подія-таймер | Минуло 3 дні без відповіді -> потік до HR (дія "Ескалація" -> "Ескальовано") |
| Керівник | Шлюз XOR | Рішення керівника? (Так / Ні) |
| Система | Задача | Списати дні з балансу (якщо "Так" -> Кінцева "Погоджено") |
| Керівник | Задача | Відхилити заявку з коментарем (якщо "Ні") |
| Працівник | Задача | Скоригувати або скасувати заявку (XOR: Коригувати -> на початок / Скасувати -> Кінцева "Скасовано") |

## 4. Замовлення на нову функцію та очікування
Керівництво вимагає створити модуль самообслуговування для відпусток з такими очікуваннями:
* **E1:** Працівник бачить поточний баланс відпустки з урахуванням нарахованих і перенесених днів.
* **E2:** Заявка створюється з датами; система сама рахує робочі дні і не дозволяє перевищити баланс.
* **E3:** Керівник погоджує або відхиляє заявку з коментарем, зокрема з мобільного пристрою.
* **E4:** Календар команди показує відсутності і попереджає про накладання.
* **E5:** Керівник отримує нагадування про непогоджені заявки; працівник — про зміну статусу.
* **E6:** HR-менеджер бачить звіт по залишках відпусток.
